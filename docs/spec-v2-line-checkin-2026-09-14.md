## 1. 背景と目的

- 参加者が増え（直近13名/回）、来月から月4回開催。管理者が画面で何十人分もチェックを入れる作業が限界
- 参加者が**自分のスマホで会場のQRを読むだけ**で出席が記録され、残り回数・参加履歴を本人が見られるようにする
- 回数券の残り・購入・未収・過去の出席回数・今日の出席人数を**1つのアプリで一括管理**する

## 3. 全体の構成

```
【会員のスマホ】                【クラウド】                     【管理者（耕平さん）】
会場の紙QR（アプリのURL）を読む
  ↓ ブラウザで開く。端末に合鍵があれば本人確定
checkin（会員画面）
  ├ 初回：名前＋暗証番号4桁を入力 → 承認待ち（合鍵を端末に保存）
  ├ 別端末：名前＋暗証番号でログイン → 合鍵を保存
  └ 毎回：［出席する］ ──POST──→ 受付GAS（新規） ──1行追記──→ 新スプレッドシート
                                    ├ 出席タブ に1行                     5タブ（会員/出席/購入/開催/料金）＋設定
                                    └ 会員タブ の残り回数を1減らす            ↑
  ← 残り◯回・参加◯回目・参加率・今日の出席者                                │
                                                                admin（管理画面）
                                                                今日の一覧／取消／代打ち／承認待ち／番号リセット

```

## 5. データ（新スプレッドシート・5タブ・1件1行）

**追記が基本。既存行の書き換えは「残り回数」「状態」「入金」など明示した列だけ。**

### 5.1 会員

| 列 | 項目 | 内容 |
|---|---|---|
| A | 会員ID | `M` + 連番（旧IDは備考に保持） |
| B | 表示名 | 本人が入力したあだ名。変更可。**退会以外で重複不可** |
| C | 暗証番号ハッシュ | `SHA-256(PIN_PEPPER + ":" + 暗証番号)`（PIN_PEPPER はスクリプトプロパティのランダム文字列）。生の番号は保存しない |
| D | トークン | 端末に渡す合鍵（ランダム32文字）。番号リセットで作り直す＝全端末ログアウト |
| E | 区分 | 一般／運営会員／免除 |
| F | 管理者 | TRUE/FALSE |
| G | 状態 | 承認待ち／有効／休会／退会 |
| H | 残り回数 | 回数券の残り。出席・付与で増減 |
| I | 入会日 | **初めて出席した日**（体験含む）。初回の出席記録時に GAS が自動でセット。移行分は参加票の最初の出席日。管理画面で直せる |
| J | 承認日時 | |

## 6. 受付GASの窓口

すべて `POST`。`login`・`register` 以外は端末の合鍵（`token`）を同送し、GASは①会員タブでトークンを引く ②処理、の順。

| action | 誰が | 中身 |
|---|---|---|
| `register` | 誰でも | 表示名＋暗証番号4桁を受け取り、会員タブに「承認待ち」で1行追加（ハッシュ・トークン付き）。トークンを返す＝端末に合鍵が入る。同名があれば拒否 |
| `login` | 誰でも | 表示名＋暗証番号 → 一致すればトークンを返す。失敗は「ログイン失敗」を+1、10回で拒否 |
| `changePin` | 会員 | 暗証番号の変更（現在の番号が要る） |
| `me` | 会員 | 自分の状態（承認待ち／残り回数／通算参加回数／**参加率・入会日**／未収／今日の出席状況）と、今日の開催（**第◯回**）・出席人数・出席者の表示名。**購入履歴・金額は返さない** |
| `rename` | 会員 | 表示名の変更 |
| `checkin` | 会員 | §7 の判定 → 出席タブに1行追記＋残り回数を更新。**LockService で排他** |
| `admin.today` | 管理者 | 今日の出席一覧（取消済みも薄く表示） |
| `admin.cancel` | 管理者 | 出席を「取消」にし、消化していた券を戻す |
| `admin.manualCheckin` | 管理者 | 代打ち。会員IDと支払い種別を指定して出席追記（判定は `checkin` と同じ） |
| `admin.pending` / `admin.approve` | 管理者 | 承認待ち一覧／「既存の会員IDに紐づけ」または「新規会員として登録」 |
| `admin.members` / `admin.updateMember` | 管理者 | 会員一覧／区分・状態・管理者フラグ・備考の変更 |
| `admin.resetPin` | 管理者 | 会員の暗証番号を新しい4桁に設定し、トークンを作り直す（忘れた人の救済。**MVP-1 に含める**） |
| `admin.purchase` / `admin.markPaid` | 管理者 | 券の付与（入金済み／未収を選ぶ）／未収→入金済み |
| `admin.sessions` / `admin.upsertSession` | 管理者 | 開催の一覧・登録・変更 |
| `admin.prices` / `admin.updatePrice` | 管理者 | 料金表 |
| `admin.stats` | 管理者 | 人ごとの通算出席・参加率（出席タブ＋開催タブから計算）・月別の出席人数・未収合計 |
| `admin.payments` | 管理者 | **入金一覧**：購入タブ（券）＋出席タブの都度・体験を、日付順に1本にして返す。月別合計つき |

**冪等性**：`checkin` は「同一開催ID＋会員ID で有効な行があれば何もしない」。`admin.cancel` は取消済みなら何もしない。通信が切れて2回押しても壊れない。

## 7. 出席の判定（`checkin`）

```
承認待ち・休会・退会 → 「まだ承認されていません」等で拒否
今日の開催が無い     → 「今日は練習日ではありません」
今日すでに有効な出席 → 「本日は受付済みです」（残り回数を再表示）
区分＝免除           → 種別「免除」・金額0・消化なし で記録
残り回数 ≥ 1        → 種別「券」・金額0・消化あり・残り回数 −1
残り回数 = 0        → 画面で選ばせる：
                       ［今日は都度参加 1,200円］→ 種別「都度」・消化なし
                       ［5回券を買う 3,980円/2,980円］→ 購入タブに「未収」で1行＋残り回数+5 → 種別「券」で消化（残り4）
入会日が空（初回）  → ［体験のみ 500円］→ 種別「体験」
                       ［今日入会する］→ 購入（未収）→ 種別「入会」・金額0・消化なし（5回は次回から）
出席を記録したとき   → 会員タブの入会日が空なら**今日をセット**（種別を問わず。体験だけの人も入る）
```

**参加率の計算**（`me` / `admin.stats`）：
`分母 = 開催タブのうち 入会日 ≤ 日付 ≤ 今日 かつ 状態 ≠ 中止 の件数`（開催を「終了」に変える操作は不要）、`分子 = そのうち本人の有効な出席がある件数`。開催が1件も無ければ「―」。

- 本人のスマホから券を買った場合は**必ず「未収」で記録**し、管理者が入金を確認したら入金済みにする（お金の受け取りは人が見る）
- 「券を持っている人が今日はあえて都度払い」は**選べない**（券優先）

## 10. セキュリティ

- 本人特定はトークン（ランダム32文字・会員タブ）。フロントから会員IDや表示名で本人を指定させない
- 暗証番号はハッシュのみ保存（`SHA-256(PIN_PEPPER:番号)`。PIN_PEPPER はスクリプトプロパティのランダム文字列）。生の番号はシートにもログにも残さない
- 総当たり対策：連続10回失敗でその会員はロック（管理者のリセットで解除）。GAS の応答速度も自然な抑止になる
- 4桁の暗証番号は「なりすまし防止」としては弱い。守っているのは出席記録と残り回数だけで金銭は動かない、という前提で採用（§2-3）
- 管理者APIは会員タブの管理者フラグで判定（フロントの表示だけで守らない）
- シートIDは GAS のスクリプトプロパティ。**コード・HTMLに直書きしない**。`config.js` に置くのは GAS の公開URLのみ
- 会員に返す情報は §2-10・§2-18 の範囲に絞る（他人の残り回数・未収・トークンは返さない）
- エラーは日本語の定型文で返し、GASの生エラーを画面に出さない

## 11. リスクと対応

| リスク | 対応 |
|---|---|
| 同時に複数人が出席を押して行が壊れる | 追記専用＋LockService。残り回数の更新もロック内で行う |
| 家から出席を押す | 開催日のみ受付＋管理者の取消。悪用が続くなら「毎回変わるQR」を後から足せる（開催タブに当日コードを持たせるだけ） |
| スマホを持たない・忘れた会員 | 代打ち（§2-6） |
| 暗証番号・名前を忘れる | 管理者のリセット／会員一覧で検索（§2-20） |
| 他人の名前と番号でなりすます | 出席記録だけで金銭は動かない。管理画面の「今日」で見慣れない出席は取消できる |
| GASの反応が遅い（1〜2秒） | ボタン押下後に「記録中…」を出し、二度押しを防ぐ。冪等なので二度押しでも壊れない |
| 承認が間に合わず会場で止まる | 管理画面の承認待ちは会場でスマホから操作できる。急ぎなら代打ちで記録し、後で紐づける |
| ブラウザのサイトデータ削除で合鍵が消える | 名前＋暗証番号で再ログインすれば復活。データは会員IDに紐づくので消えない |
| 移行で名前の対応を間違える | 移行後1か月は旧アプリと並走し、残り回数を突き合わせる |
| 既存GAS・シートを壊す | 読むだけ。新シートは別ファイル |
