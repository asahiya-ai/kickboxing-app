# 参加管理アプリ v2 仕様書

> **この版の位置づけ**：2026-09-14 の相談で「既存アプリへの追加（v1.2）」をやめ、**作り直し**に切り替えた版。
> v1.2 との主な違い：①受付した瞬間に出席確定・券消化（管理者の「確定」なし）②本人特定を LINE ログインに
> ③準備／フォローのチェックを廃止 ④免除区分の追加 ⑤データを「1件1行」の新シートに移行。
> **実装は1行も書いていない。**「開発してください」の指示待ち。

---

## 1. 背景と目的

- 参加者が増え（直近13名/回）、来月から月4回開催。管理者が画面で何十人分もチェックを入れる作業が限界
- 参加者が**自分のスマホで会場のQRを読むだけ**で出席が記録され、残り回数・参加履歴を本人が見られるようにする
- 回数券の残り・購入・未収・過去の出席回数・今日の出席人数を**1つのアプリで一括管理**する

## 2. 決定事項（2026-09-14 の相談で確定）

| # | 項目 | 決定 |
|---|---|---|
| 1 | 作り方 | **作り直し**。既存 `index.html`・既存GAS・`AppData!A1` は触らず、新しいシート＋新しいGAS＋新しい画面で作る。旧アプリは移行完了まで並行して残す |
| 2 | 受付の確定 | **QRを読んで「出席する」を押した瞬間に確定**。回数券もその場で1減る。管理者は当日一覧から**取り消す**だけ |
| 3 | 本人特定 | **LINEログイン**（個人アカウント）。LINE公式アカウントとは別の無料機能。メッセージは一切送らない（通数を消費しない） |
| 4 | 表示名 | LINEの名前は使わない。**初回ログイン時に倶楽部での名前（あだ名）を本人が入力**。あとから設定で変更可 |
| 5 | 既存会員との紐づけ | 初ログインは「**承認待ち**」。管理者が「既存の◯◯さん」または「新規会員」として承認する。**承認前は出席を押せない** |
| 6 | LINEを使わない会員（1名） | 管理画面の「**代打ち**」で管理者が出席を記録。QR忘れ・電池切れの救済も同じ機能 |
| 7 | 準備／フォローのチェック | **廃止** |
| 8 | 会員区分 | 一般／**運営会員**（券2,980円）／**免除**（お金も券も動かさず出席回数だけ数える）。**管理者が付け外し**する。自動判定（ホット会員案）は採用しない |
| 9 | 会場QR | **印刷して貼りっぱなしの固定QR**。開催登録のある日だけ受付。家から押された場合は管理者が取り消す |
| 10 | 他の会員の情報 | ログイン済みの会員には**今日の出席人数と出席者の表示名**を見せる。それ以外（残り回数・未収など）は本人と管理者だけ |
| 11 | 管理者 | 耕平さん（＋指定した役員）のLINEアカウントに管理者フラグ。別のパスワードは作らない |
| 12 | 本人による取り消し | **無し**。間違えたら管理者に言う |
| 13 | 料金 | 初回体験500円／都度1,200円／5回券3,980円（運営会員2,980円）。**料金表として持ち、管理画面で変更可**（v1.2 §3.1 を継承） |
| 14 | 未収 | **回数券の代金だけ**追いかける。都度・体験の現金は未収を持たない。未収でも出席できる（v1.2 §3.2 を継承） |
| 15 | 土台 | GAS ＋ Google スプレッドシート（新規）＋ GitHub Pages（静的HTML、LIFFとして開く） |

## 3. 全体の構成

```
【会員のスマホ】                【クラウド】                     【管理者（耕平さん）】
会場の紙QRを読む
  ↓ LINEで開く（LIFF）＝この時点で本人確定
checkin（会員画面）
  ├ 初回：あだ名を入力 → 承認待ち
  └ 毎回：［出席する］ ──POST──→ 受付GAS（新規） ──1行追記──→ 新スプレッドシート
                                    ├ 出席タブ に1行                     5タブ（会員/出席/購入/開催/料金）
                                    └ 会員タブ の残り回数を1減らす            ↑
  ← 残り◯回・参加◯回目・今日の出席者                                        │
                                                                admin（管理画面）
                                                                今日の一覧／取消／代打ち／承認待ち
                                                                券の付与・未収／料金表／開催登録／集計
```

| 2 | 管理画面 `admin.html` | 同上。同じLIFFで開き、管理者フラグの無い人には出さない |

## 6. 受付GASの窓口

すべて `POST`（LIFF IDトークンを同送）。GASは①トークンを検証 ②会員タブで userId を引く ③処理、の順。

| action | 誰が | 中身 |
|---|---|---|
| `me` | 会員 | 自分の状態（承認待ち／残り回数／参加回数／未収／今日の出席状況）と、今日の開催・出席人数・出席者の表示名 |
| `register` | 会員（初回） | 表示名を受け取り、会員タブに「承認待ち」で1行追加 |
| `rename` | 会員 | 表示名の変更 |
| `checkin` | 会員 | §7 の判定 → 出席タブに1行追記＋残り回数を更新。**LockService で排他** |
| `admin.today` | 管理者 | 今日の出席一覧（取消済みも薄く表示） |
| `admin.cancel` | 管理者 | 出席を「取消」にし、消化していた券を戻す |
| `admin.manualCheckin` | 管理者 | 代打ち。会員IDと支払い種別を指定して出席追記（判定は `checkin` と同じ） |
| `admin.pending` / `admin.approve` | 管理者 | 承認待ち一覧／「既存の会員IDに紐づけ」または「新規会員として登録」 |
| `admin.members` / `admin.updateMember` | 管理者 | 会員一覧／区分・状態・管理者フラグ・備考の変更 |
| `admin.purchase` / `admin.markPaid` | 管理者 | 券の付与（入金済み／未収を選ぶ）／未収→入金済み |
| `admin.sessions` / `admin.upsertSession` | 管理者 | 開催の一覧・登録・変更 |
| `admin.prices` / `admin.updatePrice` | 管理者 | 料金表 |
| `admin.stats` | 管理者 | 人ごとの通算出席（移行前＋出席タブ）・月別の出席人数・未収合計 |

**冪等性**：`checkin` は「同一開催ID＋会員ID で有効な行があれば何もしない」。`admin.cancel` は取消済みなら何もしない。通信が切れて2回押しても壊れない。

## 7. 出席の判定（`checkin`）

```
承認待ち・休会・退会 → 「まだ承認されていません」等で拒否
今日の開催が無い     → 「今日は練習日ではありません」
今日すでに有効な出席 → 「本日は受付済みです」（残り回数を再表示）
区分＝免除           → 種別「免除」・金額0・消化なし で記録
残り回数 ≥ 1        → 種別「券」・金額0・消化あり・残り回数 −1
残り回数 = 0        → 画面で選ばせる：
                       ［今日は都度参加 1,200円］→ 種別「都度」・消化なし
                       ［5回券を買う 3,980円/2,980円］→ 購入タブに「未収」で1行＋残り回数+5 → 種別「券」で消化（残り4）
入会日が空（初回）  → ［体験のみ 500円］→ 種別「体験」
                       ［今日入会する］→ 購入（未収）＋入会日を今日に → 種別「入会」・金額0・消化なし（5回は次回から）
```

- 本人のスマホから券を買った場合は**必ず「未収」で記録**し、管理者が入金を確認したら入金済みにする（お金の受け取りは人が見る）
- 「券を持っている人が今日はあえて都度払い」は**選べない**（券優先）

## 10. セキュリティ

- LIFF IDトークンを受付GASが検証（LINE の verify API）。userId の偽装を防ぐ
- 管理者APIは会員タブの管理者フラグで判定（フロントの表示だけで守らない）
- チャネルシークレット・LIFF ID・シートIDは GAS のスクリプトプロパティ。**コード・HTMLに直書きしない**。`checkin.html` に置くのは LIFF ID のみ（公開前提の値）
- 会員に返す情報は §2-10 の範囲に絞る（他人の残り回数・未収・LINE userId は返さない）
- エラーは日本語の定型文で返し、GASの生エラーを画面に出さない

## 11. リスクと対応

| リスク | 対応 |
|---|---|
| 同時に複数人が出席を押して行が壊れる | 追記専用＋LockService。残り回数の更新もロック内で行う |
| 家から出席を押す | 開催日のみ受付＋管理者の取消。悪用が続くなら「毎回変わるQR」を後から足せる（開催タブに当日コードを持たせるだけ） |
| LINEを使わない会員 | 代打ち（§2-6） |
| GASの反応が遅い（1〜2秒） | ボタン押下後に「記録中…」を出し、二度押しを防ぐ。冪等なので二度押しでも壊れない |
| 承認が間に合わず会場で止まる | 管理画面の承認待ちは会場でスマホから操作できる。急ぎなら代打ちで記録し、後で紐づける |
| 移行で名前の対応を間違える | 移行後1か月は旧アプリと並走し、残り回数を突き合わせる |
| 既存GAS・シートを壊す | 読むだけ。新シートは別ファイル |
